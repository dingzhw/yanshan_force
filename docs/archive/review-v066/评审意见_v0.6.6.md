## 一、版本演化历史摘要

### 1.1 演进主线概览

项目遵循语义化阶段版本管理，每个里程碑保留独立可运行目录（`playtest/windows-v0.x`）与源码检查点（`docs/checkpoints/source-*.zip`），存档 `user://profile-v01.json` 保持向下兼容。整体可划分为四个阶段：

| 阶段 | 版本区间 | 主题 | 引擎/渲染基线 |
|---|---|---|---|
| 原型奠基期 | v0.1 ~ v0.3（备份/归档 tag） | 地面修复、移动、路线、词兵战斗雏形、跨学科题库 | Godot 4.7 / GL Compatibility |
| 核心玩法成型期 | v0.4.0 ~ v0.5.6 | 山脚至竹林 100m 精修段 → 搜打撤战斗/经济闭环 → 第一人称拟真手臂、阶梯英语解锁、生态远景 | GL Compatibility（标准画质 + 核显低负载双入口） |
| 内容纵深扩展期 | v0.6.0 ~ v0.6.4 | 江南人文地标 → 水系生灵与战术身法 → 词兵波次重塑与性能危机修复 → 秘境探索与双行动 → 摸金大红 → 青绿美术与近战重塑 | GL Compatibility，低画质手动档 |
| 现代管线与智战期 | v0.6.5 ~ v0.6.6 | 太平村云海美学 + **Vulkan Forward+ 双档管线** → 词兵掩体战术 AI 重写 | Vulkan Forward+（桌面）/ mobile（移动），F6 双档 |

### 1.2 主要版本节点与功能变化

- **v0.4.0（2026-11-07，首个正式里程碑）**：约 100m A 山脚营地至 B 竹林补给点连续山路，初版 YS-04 步枪动画、两处词兵巡逻区、三处跨学科探索点（英语 `next to`、数学平移、古诗《山居秋暝》）、100 分撤离闭环。验收 182 项通过；打包标准画质实测 `average_fps≈99.8 / P95=10ms`（RX 6600）。当时已记录「Vega 8 核显实测、孩子 5–8 分钟节奏尚未验证」。
- **v0.5.0（11-12，告别无脑通关）**：撤离门槛 `100→260 分`、必须攻克 ≥1 前哨；三类战术兵种与三哨所防线；可充能护盾与医疗包；**CipherTerminal 拼写破译开箱**（前 2 次拼对「完美破译」，连续错 2 次展示答案并朗读）；五级稀有度战利品；离线英文 TTS、智能干扰项与 `mastery` 掌握度持久化。
- **v0.5.1（11-12，学习机制关键取舍）**：阶梯式英语解锁 **单词 → 词组 → 课本整句**（Tier1 单词+词组、Tier2 词组+短句、Tier3 三关连破），等价判分（标点省略、`It's↔It is`、英美拼写）；修复满包开箱、错词点击发音未绑定等遗留问题。
- **v0.5.2 ~ v0.5.6（11-12~13）**：39 骨骼 CC0 写实第一人称手臂（v0.5.2）；双武器匕首、枪匠 2.0、B 区重装首领（v0.5.3）；立体跳格子、双语战地线报、雷达空投（v0.5.4）；溪流与动植物生态、围栏稻田远景（v0.5.5）；`TONE_MAPPER_FILMIC` 与远景山岚调优（v0.5.6）。
- **v0.6.0（11-13，古今交织）**：望稻亭、青石拱桥与界碑、诗碑亭、古樟土地石龛、青石板古道五大江南人文地标。
- **v0.6.1 / v0.6.1.1（11-14）**：下切鹅卵石溪床与江南乔木竹林换代、8 类 52 只生灵；蹲伏/卧倒/探头三态身法、取消脱战自动回血、9 类骨骼动物行为。**此处埋下性能危机与两处明确遗留决策**：「深度战术 AI 留待 v0.7.0 专项升级」。
- **v0.6.1.2（11-14，性能危机修复）**：全山 6 营地 × 3 波 × 5 词兵波次重塑、头部 1 枪/词盾 2 枪、打错零伤害且敌攻叠加 25%；根因是「镂空树叶每帧约 37.5 万三角面实时阴影贴图瓶颈」，通过剥离镂空叶冠阴影 + 合批树冠地影 + 36m×36m 空间分块视锥剔除 + O(1) 高度网格，标准画质帧率由约 `31–39 FPS` 跃升至平均 `168.9 FPS`（P95=8.8ms）。这是全项目最关键的一次架构级性能修复。
- **v0.6.2 / v0.6.2.1（11-15）**：迷踪竹石阵、烟霞古洞（双厅溶洞、先民岩画、寒潭茶灶）；普通/机密双行动模式。验收 339/339、343/343，帧率 216.9 / 200+ FPS。
- **v0.6.3（11-16，摸金重塑）**：6 阶稀有度与「旷世·大红」奇迹池、31 件双语藏品、放大镜逐格鉴定、露天 3D 刷货/掏鸟窝/波次掉落、`[B]` 背包、`[I]` 3D 检视台、营地奇珍图鉴。360/360，184 FPS。
- **v0.6.4（11-18，青绿美术与近战）**：双肩封口 + 锁肩双骨 IK 根除挥刀断臂、青绿水墨树竹体积着色器（零树影开销）、6 分件 YS-04、飞檐机关词卫。363/363，160.6–192.5 FPS。
- **v0.6.5（11-18，管线切换）**：对标太平村重塑云海梯田与徽派民居；**渲染从 GL Compatibility 升级为 Vulkan Forward+**（Filmic + FXAA），新增 `[F6]` 核显均衡档（0.90× 渲染倍率 + 轻量解析雾）；修复据点波次连轴转（8.5s 空营 + 14s 免战）。364/364。
- **v0.6.6（11-18，智战烟山，当前最新版）**：词兵战术 AI 彻底重构（掩体评分认领 `claim_tactical_cover`、移动压制点射 `try_moving_suppression`、答案词盾防遮挡、普通 44m/机密 86m 追击边界）；普通 3~4、机密 3~6 随机兵力；`15s+15s=30s` 休整窗口；366/366。

### 1.3 架构与引擎相关变化

1. **渲染管线两次转折**：v0.1 起确立 GL Compatibility（核显友好、关闭屏幕空间 AA）→ v0.6.5 升级 Vulkan Forward+ 主管线并保留 F6 核显双档。`project.godot` 现为 `renderer/rendering_method="forward_plus"`、`mobile` 移动端、`msaa_3d=0` + `screen_space_aa=1`。注意：切换是「主管线升级 + 双档并存」，而非彻底替换——v0.6.6 巡检报告仍显示低负载档以 `gl_compatibility` 运行。
2. **资产管线工业化**：Blender 4.5 建模脚本（`tools/build_*.py`）+ Python PIL 程序化贴图（`tools/generate_*_textures.py`）+ SFX 合成 + CC0/CC BY 素材溯源（`game/THIRD_PARTY.txt`）。资产从早期卡通白模演进到 39 骨骼写实手臂、MultiMesh 合批地标、体积着色器。
3. **战斗 AI 三阶段**：v0.5.0 三兵种协同 → v0.6.1.2 波次/仇恨/部位判定 → v0.6.6 掩体战术状态机（原「留待 v0.7.0」的深度 AI 被提前实现）。
4. **性能工程体系化**：36m×36m MultiMesh 分块（恢复 GPU 视锥剔除）、O(1) 双线性高度网格、距离休眠（词兵 36m / 动物 42m / 洞穴灯 32m）、Label3D 与小地图 20Hz 节流、多级缓存。

### 1.5 版本演化小结

v0.4.0→v0.6.6 的演进呈现清晰的「**先玩法闭环、再内容纵深、后工程提质**」轨迹：早期用约 6 周把「搜打撤 + 英语答题」闭环跑通（v0.4–v0.5），中期以近乎每日一版的节奏堆叠江南人文与摸金内容（v0.6.0–v0.6.4），后期集中处理性能危机与现代化管线（v0.6.1.2 / v0.6.5 / v0.6.6）。累计回归断言从 182 增至 366，形成较完整的可追溯证据链（git tag + release-*.json + checkpoints + v*checks 检查目录）。主要结构性遗留集中在**教学有效性实证**、**目标核显实测**与**文档同步**三处。

## 三、总体评审结论

v0.6.6 是一个**功能完成度高、工程可追溯性强、性能工程扎实的少儿英语学习 FPS**。它在「可玩性 + 视觉表现 + 帧率」三维上已达到较高水准（366/366 回归、标准画质 160–192 FPS、Vulkan Forward+ 现代管线、掩体战术 AI），作为开源供 Fork/魔改的学习游戏基座是合格且富有吸引力的。

但三方向评审揭示出一个共同的结构性矛盾：**工程投入的高度与教学有效性的深度不匹配**。近 10 个版本的迭代资源大量投向画面、玩法与性能，而英语学习核心仍停留在「识别射击 + 拼写开箱 + 计数式掌握度」的计数模型层面——缺少间隔重复、跨局错词本、产出性拼写保障与学习数据可视化。同时，`main.gd`(1601 行)、`slice_world.gd`(2861 行) 等上帝类与普遍硬编码，正在成为后续迭代（尤其 v0.7.0 的「学战融合」目标）的主要摩擦点。

综合评级：**可继续开发潜力 中上 / 性能优化空间 中（已深度优化，剩余为结构性改良）/ 英语学习有效性 中偏低（形式丰富但教学闭环不完整）**。

建议 v0.7.0 把重心从「加内容」真正转向规划中承诺的「学战融合」，优先补齐 SRS 复习机制与教学实证，同时启动对上帝类的模块化拆分，避免学习系统改造被耦合架构拖累。

## 四、专项评审一：引擎可继续开发潜力

### 4.1 优势

- **现代化且可降级的渲染基座**：`project.godot` 采用 Vulkan Forward+ 主管线 + mobile 移动管线 + F6 核显均衡档（0.90× 倍率、关闭 SSAO/体积雾/阴影），通过 `RenderingServer.get_current_rendering_method()` 运行时判定优雅降级，兼顾画质与低配可用，为后续画质分级、平台扩展留好接口。
- **职责划分基本清晰的模块层**：`layout.gd`（纯静态地形/坐标函数，无状态易测）、`rules.gd`（规则/经济/掌握度）、`combat.gd`（战斗调度）、`slice_world.gd`（世界生成）、`exploration.gd`（探索）各司其职；词库通过扫描 `wordpacks/*.json`（`schema_version==1`）自动加载，「零代码换词库」入口可用。
- **成熟的缓存与性能基建**：scene/sound/sfx/纹理/材质多级缓存、脏标记（bag_signature）、实例缓存等已成体系，新增内容可复用。
- **自动化回归覆盖面广**：9 大套件 366 项断言，且新增特性（如 v0.6.6 掩体认领、移动压制、30s 休整）均有对应断言，具备「改动可验证」的工程基础。
- **资产管线可复现**：Blender/PIL/SFX 脚本与 CC0 溯源齐全，后续换皮、加地标、加词卡有可复用工具链。

### 4.2 不足

- **上帝类与超大文件**：`main.gd`(1601)、`slice_world.gd`(2861)、`combat.gd`(1318)、`wildlife.gd`(1229) 远超可维护阈值；`main.gd` 持有全部子系统并双向直接读写字段（无事件/信号层），任一改动易连锁。
- **输入与配置硬编码**：`project.godot` 无 `[input]` action 映射，按键散落各脚本硬编码；UI 全为像素级 `Rect2(...)`；爆率/战斗数值/教学文案多为魔数。
- **命名与内容错配**：`grade5a.json` 实为跨学科题库（math/poem/intel），英语 `next to` 线索硬编码在 `exploration.gd`，易误导维护。
- **版本文案硬编码**：`VERSION="0.6.6"`、菜单更新说明写死在代码，发版需多处手改。
- **物理/渲染配置单薄**：未启用 Jolt 物理；无动态分辨率自适应；MSAA 关闭使画质上限受限。

### 4.3 风险

- v0.7.0「学战融合 + 艾宾浩斯靶向巩固」若要深度改造出题/掌握度/`main.gd` 判分链路，将直接触碰上帝类，**改造成本与回归风险高**。
- 硬编码 UI（像素 Rect2）在不同分辨率/缩放下易错位，跨平台适配成本上升。
- 文档滞后（`project-scope.json` 停 v0.6.0、README 示例 `--ver 0.6.4`）会误导新贡献者与二次开发者。

### 4.4 可改进点（方向性）

1. 引入信号/事件总线，逐步把 `main.gd` 的判分、出题、发音、存档拆为独立服务；优先抽离「学习域」为可独立测试的模块，为 v0.7.0 铺路。
2. 建立 `[input]` action 映射与 UI 布局常量/锚点，替换硬编码按键与像素坐标。
3. 统一版本信息到单一数据源（如 `version.cfg`），由 README/菜单/检查脚本读取。
4. 修订 `project-scope.json`、README 示例命令与渲染说明，消除 v0.6.6 现状不一致。
5. 将 `grade5a.json` 更名或拆分英语/跨学科题库，消除命名歧义。

## 五、专项评审二：性能优化空间

### 5.1 优势（已做到的）

- **视锥剔除与合批**：36m×36m MultiMesh 分块（`slice_world.gd:_batch_direct`）恢复 GPU 视锥剔除与逐扇区可见距离，是性能回血的关键设计。
- **O(1) 高度查询**：`layout.gd:fast_height` 预烘焙 121×157 双线性网格 + 整数点缓存，替代每帧百余次折线求值。
- **多级距离休眠**：词兵 36m、动物 42m、洞穴灯 32m 淡出无阴影、雨丝低画质关闭、`visibility_range_end` 广布。
- **阴影成本精算**：关闭镂空叶冠/竹叶双向阴影（每 split 省约 29 万三角面），以单 draw-call 树冠投影盘替代；方向光 2 splits / 52m。
- **节流与缓存**：小地图 20Hz 重绘、多重缓存体系。实测标准画质 160–192 FPS、低负载档约 100 FPS（RX 6600 / Vega 8 口径不同）。

### 5.2 不足

- **CPU 端粒子**：雨丝用 `CPUParticles3D`（amount=110），CPU 模拟开销，可 GPU 化。
- **无动态分辨率自适应**：仅有手动 0.90× 低画质档，无法按实时帧率动态升降。
- **每帧潜在开销集中于 `main.gd`**：UI、判分、HUD 更新集中在主循环，缺少帧预算拆分。
- **光照/阴影为静态妥协**：仅方向光投影，点光源靠距离淡出规避，规模化场景会重新触及瓶颈。
- **诊断数据口径不一**：`docs/diagnostics/` 快照均为低负载档，缺少与标准画质同口径的长期帧率基线。

### 5.3 风险

- 继续堆内容（v0.6.2–v0.6.5 已验证每轮内容扩张都会把帧率从 216 拉到 160 区间）将持续侵蚀性能余量，缺乏自动化的帧率回归门禁。
- 目标核显 Vega 8 从未实测——所有「核显友好」结论为推断，低端设备上 30s 休整期与掩体 AI 新增的射线/评分计算可能放大卡顿。

### 5.4 可改进点（方向性）

1. 增加**帧率回归门禁**：把 `performance_tour.gd` 纳入 CI/发版检查，统一标准画质与低负载两档口径，防止内容扩张导致帧率回退。
2. 引入 Godot 4 动态缩放（`scaling_3d_scale` 按帧时间自适应）或 TAA/FSR 类上采样，替代固定手动档。
3. 将 `CPUParticles3D` 雨丝/命中粒子迁移到 `GPUParticles3D`。
4. 对 `claim_tactical_cover` 的掩体评分、`Label3D` 更新做分帧摊平与脏标记，降低 spikes。
5. 补做 Vega 8 目标机实测，把 `target_vega8_tested` 从 false 转为真实验收结论，并据此校准双档阈值。

## 六、专项评审三：英语学习有效性

### 6.1 优势

- **多模态、多题型覆盖**：中文释义→英文射击识别、离线 TTS 发音（`[X]/[Tab]`）、听力辨词（每 5 题触发）、密码箱**拼写**产出、野生动物英文例句与探索语境句，覆盖识别与产出两类任务。
- **词库数据质量高**：`jiangsu-5a-2026.json` 175 条（word 125 / phrase 34 / sentence 3 / proper_name 13，core 132，8 单元），带教材页码、PDF 页码与 sha256 溯源；支持 aliases 等价答案。
- **抗猜测设计**：`_pick_smart_distractors` 按词性/短语/单元/首字母打分选干扰项，避免靠长度或大写盲猜；答错词每 6 题强制复现。
- **掌握度与错词追踪**：`rules.gd` 维护 seen/correct/wrong/spelled，`correct>=2 且 correct>wrong` 判为掌握，`word_priority` 依错次加权；局末错词本可点击朗读。

### 6.2 不足（教学硬伤）

1. **无真正的间隔重复/复习曲线**：`word_priority` 仅是基于累计对错的静态加权，无时间间隔、无艾宾浩斯梯度、无记忆稳定性模型；`mastered_count` 是永久累计计数，不随时间衰减。README 承诺的「艾宾浩斯靶向巩固」尚未实现。
2. **错词本生命周期过短**：`wrong_words` 每次开局清空（`main.gd` L879），复盘仅本局有效；跨局持久化的 mastery 计数没有驱动跨局错词重排，新开局仅「重复入队一次」力度不足。
3. **拼写产出可被「抄答案」绕过**：`cipher_terminal.gd` 第 1 次错给前缀提示、第 2 次错**直接展示完整答案并允许对照输入通过**，产出性练习的有效性被打折；识别题仍为主要得分方式。
4. **反馈偏浅**：选择题反馈仅「正确答案：english — chinese」，无用法辨析、例句回放或错因分类。
5. **TTS 单一且无降级**：仅取系统第一个英文语音 `voices[0]`，无英美音/语速选择；headless/QA 下静默，无失败提示。
6. **别名覆盖极低**：aliases 仅 1/175，主要靠 `_canonical` 硬编码缩写与英美拼写对兜底，扩展新词形维护成本高。
7. **无学习数据可视化**：结果页仅「掌握 N/175」一个数字，无正确率趋势、掌握曲线或单元维度分析。
8. **教学有效性无真人实证**：Vega 8 与孩子节奏未测的遗留之外，答题正确率提升、记忆保持率等核心教学目标从未被量化验证。

### 6.3 风险

- 游戏性持续加码（摸金爆率、战术 AI、30s 休整）可能进一步挤压有效学习时长——玩家可能把游戏当射击/摸金玩，而「看词→作答」沦为获取战利品的门槛，学习动机被游戏动机稀释。
- 若 v0.7.0 仍不落地 SRS，「艾宾浩斯靶向巩固」将持续停留在 Roadmap 文案，损害项目对家长/教师的核心承诺。

### 6.4 可改进点（方向性）

1. **落地轻量 SRS**：为词条增加 `last_reviewed / interval / ease / stability` 字段，基于 `mastery` 实现 1d/2d/4d/7d/15d 复习梯度；到期词优先入队。
2. **错词本跨局持久化**：将 `wrong_words` 写入 `profile` 存档，开局按「到期错词 + 新词 + 低掌握词」混合编排。
3. **保障产出性拼写**：改为「提示递进但不直接给全文」，或通过「间隔后重新拼写正确才算掌握」，杜绝照抄过关。
4. **丰富反馈**：答错给例句与用法辨析，复用 `wordpacks` 的 sentence 字段与野生动物例句。
5. **学习仪表盘**：按单元/词性展示正确率趋势与掌握曲线，服务家长/教师观察。
6. **补做教学实证**：以「5–8 分钟一局」为单位记录前后测正确率与一周保持率，把 `human_5_to_8_minute_pacing_tested` 从 false 转为真实结论。
7. **扩充 aliases** 或改为数据驱动的等价词表，减少硬编码。

## 七、按优先级的评审意见汇总

> P0 = v0.7.0 必须优先处理；P1 = 本阶段内应处理；P2 = 有条件的改良项。

### P0（最高优先级）

1. **落地间隔重复（SRS）与跨局错词本**（学习有效性）：这是项目对家长/教师的核心承诺，也是三大方向共同的短板根源。将词条扩展为带复习间隔的记忆模型，错词本写入存档并驱动开局编排；同时抽离为可独立测试的「学习域」模块（兼顾 P0 架构诉求）。
2. **拆分 `main.gd` 上帝类并引入信号层**（引擎潜力）：v0.7.0 任何学习系统改造都会触碰主控制器，先抽离出题/判分/发音/存档为独立服务，可显著降低回归风险，是后续所有学习特性的前置工程。
3. **补做教学有效性实证与目标机实测**（风险闭环）：以真实孩子样本验证 5–8 分钟节奏与词汇保持率，并在 Vega 8 上实测双档帧率，把两个长期 `false` 的验收标记转为真实结论——否则所有「学习有效 / 核显友好」结论都缺乏证据支撑。

### P1（高优先级）

4. **建立帧率回归门禁**（性能）：把 `performance_tour.gd` 纳入发版检查，统一标准/低负载两档口径，遏制内容扩张导致的帧率回退（216→160 的趋势）。
5. **修正拼写可「抄答案过关」机制**（学习有效性）：改为提示递进 + 间隔重测才算掌握，保障产出性练习真实有效。
6. **同步滞后文档**（工程规范）：更新 `project-scope.json` 至 v0.6.6、渲染口径与 README 示例命令，消除对二次开发者的误导。

### P2（改良项）

7. 引入 `[input]` action 映射与 UI 锚点布局，替换硬编码按键与像素坐标；版本信息收敛到单一数据源。
8. CPU 粒子 GPU 化 + 动态分辨率自适应；掩体评分/标签更新分帧摊平。
9. 丰富答题反馈（例句/用法辨析）、新增学习数据仪表盘、扩充 aliases 数据化。
10. 处理 `walking.ogg` 告警、规划全平台导出模板；将 `grade5a.json` 更名/拆分消除命名歧义。
